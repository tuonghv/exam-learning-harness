## Commands

- `tools/run_tests.py --fast | --affected | --full [--wait] | --list | --time | --clean` (TASK-088, REQ-0096, free): tiered unit-test runner; registry `config/test_tiers.json` (slow ids, known failures, source->test map); loop = `--affected`, before commit = `--fast`, gate = `--full` once per task (detached, HEAD worktree, result `work/test-runs/<key>.json`, reused on an unchanged tree key). Guide: docs/guide/testing.md.
- `exam.py run-list EXAM [--line L] [--plans D --reports D]` / `run-compare A B` (TASK-087, REQ-0095; TASK-090, REQ-0098; free): plan runs `plans/<exam>/<line>/runs/<UTC id>[-<subject>]/` -> report runs `reports/<exam>/<line>/run-<id>/` (+ `run.json`); columns `plan run | line | subject | layout | status | model | calls | cost_usd | report runs | score`, rows grouped by line, `id (alias)` shows the old plan_run_id of a migrated run; REQ-0095 `runs/` and legacy folders stay readable (`layout runs|legacy`, line `-`); an old folder name (e.g. `dgnl2025-fix`) maps through `plans/MIGRATION.json` to its exam and line (stderr note). `A`/`B` accept a result dir, an old or new absolute path, `EXAM/ID`, `EXAM/LINE/ID` and `OLDFOLDER/OLDID`; an id in two lines exits 2 with `ambiguous: use EXAM/LINE/ID`. A report run migrated from an old reports folder (TASK-091) shows `line <L> (run unknown)` or `unknown` in the report-runs table when its run.json `link` is not exact; `report-index OLDDIR` on a moved folder exits 2 with `was moved to <run folders>`. Layout: docs/guide/report-kinds.md Run layout.
- `exam.py solve ... [--line NAME] [--exam-id ID]` / `plan-import DIR [--line NAME]` (TASK-090): default plan run `plans/<exam-id>/main/runs/<YYYYMMDD-HHMMSS>[-<subject>][-N]`; `--line fix` -> `plans/<exam-id>/fix/runs/..`; `--exam-id dgnl2025` (default: the exam file stem, unchanged) picks the exam folder and the file stem becomes the subject tag (`solve dgnl2025/English.md --exam-id dgnl2025 --line fix` -> `plans/dgnl2025/fix/runs/<stamp>-english`); `--line`/`--exam-id` cannot be combined with `--out` (exit 2); new plan.json gets `line` and `plan_exam`; the solve cache stays `plans/<exam-id>/cache` for every line; "already solved" scans every line; new reports go to `reports/<exam>/<line>/run-<id>/`.
- `exam.py publish EXAM --from LINE [--view sheet|learn] [--run ID] [--key FILE] [--no-pdf] [--plans D --reports D]` (TASK-094, REQ-0101; free): line `main` is the published line. `solve`/`report`/`report-pack`/`plan-import` into main (repo `plans/`, `reports/`) exit 2 unless `--publish` (use `--line <dev>` for tests/experiments; other roots, `--dry-run` and plans-migrate are not guarded). `publish` builds a NEW `reports/<exam>/main/run-<id>` from LINE's plan runs (its newest report-pack/publish run.json, else latest per subject), `run.json` cmd `publish` + `published_from` + `source_report_run`; earlier main runs stay; refuses `--from main`. The key of a pack is recorded in run.json (`key`, `key_sha256`) and reused by `publish` unless `--key`. `run-list` shows a `publish` column (published = main/`-`, else dev); the exam `INDEX.md` has a Lines table (main first).
- `exam.py plans-migrate [--root plans|reports] [--map FILE] [--dry-run [--write-map [--force]] | --apply --backup-dir DIR | --undo | --verify]` (TASK-090, REQ-0098; free, no AI call, `pipeline/plansmigrate.py`): moves the old sibling folders (`dgnl2025-fix/out-English` ...) into `<exam>/<line>/` by the reviewed map `config/plans_migration.json` (`folders` hand-written, `moves` generated by `--dry-run --write-map`, `report_folders`/`report_moves` for `--root reports`). `--dry-run` (default) prints the whole move table, keep list, UNMAPPED entries and the history lines it would rewrite, writes nothing. `--apply` needs `--backup-dir` outside the root (free space checked, tar.gz listing verified), moves only with `os.rename` inside the root, writes `MIGRATION.json` (state applying -> applied, per-move state, baseline counts/sha256), rewrites `plans/run-history.jsonl` keeping a `.bak`, `os.rmdir`s emptied old folders, runs the `--verify` checks and rolls back on any failure (exit 1); a second `--apply` is a no-op, an interrupted one resumes. `--undo` restores the old layout and reverse-maps the history. `--verify`: file count, bytes, every plan.json sha256, targets/old paths, kept folders, history paths (valid right after an apply; later new runs change the counts). Migrated plan.json files are never edited; the old plan_run_id stays in them (`alias`). Exit 0 ok, 1 failed/rolled back, 2 refused. `--root reports` (TASK-091, REQ-0099): every old report folder becomes report runs `<exam>/<line>/run-<id>/` (`report_folders` {old: {exam,line}}, generated `report_runs` [id, from, id_source mtime|name, link result_sha256|name|line|unknown, plan_runs, plan_line, status, superseded] and `report_moves`); id = newest file mtime (UTC) of the old folder (stamp dirs `YYYYMMDDTHHMMSSZ` = one run each, taken id -> `-2`); `--plans-root DIR` (default `plans` beside the root) is read to link plan runs by result-data `result_sha256`; after the moves each run gets `run.json` (+ `migrated_from`, `link`, `plan_line`, `status`, `superseded`) and `INDEX.md`, each line folder an `INDEX.md`; overwritten INDEX.md files are copied to `reports/MIGRATION.index/`; `--verify` = content files/bytes/sha256 of EVERY file at the mapped path (generated INDEX.md/run.json excluded), run.json + INDEX.md per run, INDEX.md == fresh render; `--undo` refuses a regenerated file that was edited, restores the originals and the whole tree sha256 for sha256.
- `exam.py run-stats stats DIR | compare A B | trend | backfill DIR...` (TASK-056) TASK-077 (REQ-0084, free, no AI call): `run-stats explain RESULT_DIR[=EXAM]... --key FILE [--exam FILE] [--pdf FILE] [--calibrate] [--json]` joins each wrong, not-answered and flagged-right answer with its calls/ (index.jsonl + NNN-reply.txt), the exam file and the PDF text (PyMuPDF, else pdftotext, else `na`) and prints one TSV row per question (`pipeline/explain.py`: extraction `fwd/rev/opt_prompt/opt_mode/ocr_page/ext` by Unicode 3-gram coverage vs the PDF, context `ctx_*`, reply path `src/multi_json/parse_now_ok/marker/..._agrees_key`, solver signals `quotes_*/alt_reading/recompute`, `primary` cause by priority infrastructure > extraction > context_not_delivered > reply_path > key_oddity_candidate > image_only > solver_reasoning > unknown) and a `# n_wrong=.. cause=k .. multi_json_questions=..` footer. The key is read only by `score_rows` (answer lists pairing a number with a letter, printed numbers); no cell holds a letter, option text or message. `--calibrate` prints fwd/rev quantiles and synthetic-defect scores (thresholds `EXTRACT_FWD_MIN`, `EXTRACT_REV_MIN`, `RELIABLE_SHARE` in explain.py). `run-stats gain --spec FILE [--json]` (spec: `exams{NAME:{key,offset?}}`, `changes[{change,learn,runs[{exam,before[],after[],offset?}]}]`, `noise{NAME:[[DIR..],[DIR..]]}`; DIR or history run_id) prints per change x exam n, before/after k with Wilson 95, fixed, regressed, noise flips, `small_n` and verdict `heldout_gain|heldout_loss|learn_only|no_measurable_change`; `board --explain TSV [--explain TSV] --gain TSV` appends the causes line and the gain rows (without them the board is unchanged). `adapters/claude.py` `_classify`: the usage-limit message (`hit your`, `-hour limit`) is `rate_limit`, so a run stops (77.11). Run metrics from result.json + run.log; history `plans/run-history.jsonl` (`--history`; legacy `reports/` and `results/run-history.jsonl` still read), appended by `solve --real` or `solve --history`. `solve` without `--out` writes a plan run `plans/<exam-id>/<run-id>/` (git-ignored: plan.json, config.json, input/exam.md, calls/NNN-{prompt,reply}.txt + index.jsonl written per call, result.json, run.log, report); `--out DIR` puts the same files in DIR. The report is built by `pipeline/report_build.py` (input = the plan run dir only; no model call, no network; deterministic, byte-identical on rebuild) into `reports/<exam-id>/<run-id>/sheet/` (report.md, answers.md, metrics.json, report.json, optional pdf). `exam.py report PLAN_RUN [--view sheet|learn] [--no-pdf] [--report-id ID] [--out DIR]` rebuilds it (many reports per plan run; same id overwrites); `report RESULT.json --out DIR` still works. `exam.py plan-import DIR [--exam EXAM.md] [--exam-id ID] [--trace FILE...] [--ingest-cache DIR]` (no model call) turns an old run dir (result.json, optional run.log) into a plan run with `source: import`, `calls_captured: false` (calls/index.jsonl rows from run.log marked `reply: "not captured"`; old solve replies were never stored); symlinks are skipped; the exam text comes only from `--exam` or a result.json `exam.path` inside DIR (else WARN, "exam not imported"); `--trace FILE` (repeatable, <= 20 MB each) copies refine traces from anywhere; ids (`--exam-id`, `--report-id`, plan.json ids) allow only `[A-Za-z0-9._-]`, no leading dot or `..` (exit 2); it also copies the dir's `*.trace.json` and the ingest reply-cache dir (`DIR/../work/ingest/<hash>`, only when it is the single one, else pass `--ingest-cache`) into `ingest/` as raw AI output; the same dir + same result.json again prints `skipped`, exit 0; no result.json exits 2; `report` then rebuilds it. `solve` prints a 3-line metrics block and report.md gets `## Metrics`. `solve --pdf FILE [--max-image-pages N]` (TASK-059; FILE = PDF or ingest doc.json; N default 4, needs --pdf else exit 2) adds one page-image call for questions that refer to a figure/table missing from the text (never key pages); config.json gets `image_pdf`/`max_image_pages` only then; the call is captured in calls/ (index line `tag: image`, `pages`; no PNGs stored); result question `source` = text|image|text+image (report.md `- Source:`); metrics counts `image_checked`/`image_changed` and the metrics line show only for such runs; `--dry-run` prints the image prompt and estimate. Without `--pdf` behaviour is unchanged. TASK-061: `--image-scope flagged|declined|doubt` (default flagged = unchanged; needs --pdf) sends cut/marker-declined (declined) and doubtful answered ids (doubt, lowest page priority) to the same one image call; same answer adds finding `image_agrees` (never PASS); TASK-076: `--adjudicate` (opt-in again after the 2025 re-solve measured no gain) runs one text call (prompt = full question block with options A-D, decide-from-text rule) for every id whose image answer differs from the text answer, any status (a FAIL included) or a tentative (non-`answered`) text answer, never one that was PASS before the image call (status UNCERTAIN `needs_review: adjudicated`; a reply equal to the text side of a FAIL keeps the FAIL; a failed or budget-stopped call keeps the pre-call result with finding `adjudication_failed`; call cap +1). `claude.extract_json(text, schema)` with a schema (solve callers) takes the LAST valid object of a reply holding several (self-correction); `refcheck` group figure sharing ignores the `Source pages:` and heading lines as key; result `run.image_scope` and metrics `image_scope`/`image_agrees`/`image_differs` only for such runs. compare exit 2 on different exam, 1 on a regression signal. TASK-063 `run-stats board [--history F] [--baseline RUN_ID|DIR] [--exam FILE] [--kind K] [--source solve|backfill|regset] [--review-pack F] [--json]` (free, no AI call, no key read): per exam kind (`subject/language/level` from result.json) coverage, quality (key = scorer `score{points,max}`, else QA proxy, else `quality unmeasured`), cost and delta vs the baseline (`--baseline`, else the previous run of the same `exam_sha256`) with verdict `better|same|regression|unmeasured`; `COVERAGE_UP_QUALITY_DOWN` when coverage rises and wrong answers rise beyond noise; exit 1 on a regression, 2 on error (different exam). History lines gain `kind`; `compute(..., quality=True)` adds a `quality` block (board only). TASK-064: a keyed declined/unanswered question now scores `points 0/1, detail not_answered` (scorer; open/no-key stay unscored), so the key rate counts refusals as not correct; `quality` gains `outcomes` (correct/wrong/unkeyed_answered/declined/unanswered/invalid, disjoint), `score` = correct/keyed with a Wilson 95% `score_ci`, `coverage`; the old rate stays as `precision` (answered-only); board pools by question (QA agree too), splits `tier official` (source regset) from `exploratory` (JSON key `tier|kind`) and labels a same-version baseline `repeat` (default baseline = latest earlier line of another commit/prompt/model); noise is an exact two-sided sign test (p>.05), fewer than 6 flips give `insufficient (flips k<6)`, no key/QA gives `unmeasured (no key, no QA)` (compare too); `trend --source` filters history. TASK-069 (REQ-0074): parsing apart from solving. A run dir with `input/assembly.json` (copied by planrun) gives the board a `parsing flagged P/N (structure flags, not accuracy)` line plus, on a key basis, `wrong: parse-suspect X solver Y` (QA basis: `differs on flagged X`); the quality/score lines keep their denominators. `board --exam FILE --structure-gold GOLD.json` (list of rows `{id, stem?, section?, instruction?, shared?, deps?, pages?}` by exam position id; exit 2 without --exam or on a bad file) prints `parsing gold n=G extraction boundary hierarchy instruction shared_ref reference cross_page tok/q~` (`-` = no gold row for the metric; `--json` adds `structure_gold`) from the pure `metrics.structure_scores(exam, gold)` (no AI call). `compute(..., structure={id: [codes]})` adds `parse_flag` rows, `counts.structure_flags`, `by_parse_flag` (keys only when given). The board also prints `input ~tok/q N (prompt bytes/4, all calls)` when every run has a run.log. Gold fixture `tests/unit/fixtures/structure_gold.json` (synthetic, `known_miss` = open gaps G5/G6). TASK-075 (REQ-0079): `solve --confidence` (free, default off; cfg `confidence` only then, so default result.json is byte-identical) adds per answered question a `confidence` tier beside the status (`verified` = PASS, `likely_ok`, `unknown`, `likely_wrong`; `core/decision.confidence`, pure, never feeds `decide()`) and `summary.confidence` counts. Negative signals only: FAIL, reviewer disagree/unsure, `image_differs`/`adjudicated`/`option_mismatch`, solver uncertainty high, or medium with a reason/issues naming another option letter (REQ-0082; structural: standalone uppercase option key, not followed by an operator); `likely_ok` needs reason `no_independent_check`, an `image_agrees`/`second_agrees` finding and no retry, malformed first round or non-low uncertainty. `verifier.option_distance` (75.1) adds a never-failing, non-independent check `option_distance` (solver `expr` vs the single-number options; finding `option_mismatch` on a unique nearest other option within 0.5-2x). `run-stats` with a key adds `confidence.by_confidence` (n, correct, wrong, precision + Wilson), `wrong_in_likely_ok`, `wrong_recall` and one `confidence:` block line (also under `quality` in the board). `solve --second-sample` (75.2, paid, default off, implies --confidence; cfg `second_sample` only then; call cap +10): after the other checks, ids that are UNCERTAIN with `no_independent_check` or a doubt reason (letter MCQ, answered) are re-solved in batches of 15 with option texts rotated (`solver.permuted`) and question order reversed, prompt = rules + context + questions + `Solve independently` (no key, no first answer, no few-shot, tag `second`); result per id: finding `second_agrees|second_differs|second_missing|second_failed|second_skipped` (source `second`, skipped = budget/call stop, or `permutation_unsafe` (stem names a letter after option/choice/phương án/đáp án/câu, an option is "all/none of the above" or names a letter, or the stem depends on another question; point names like A(1;2) are fine); never counted as differ), question `second_answer` (original letter). The reply never changes the first answer, checks or status; agree gives `likely_ok`, differ `likely_wrong`. `--dry-run` does not preview it.
- `exam.py benchmark --set FILE [--history F] ... (--mock|--dry-run|--real)` (TASK-066, REQ-0072): re-scores a fixed keyed regression set (`evals/regset.json`, git-ignored; tracked template `evals/regset.example.json`; `{v:1, set_id, items:[{id: "subject/name", input, key, key_basis}]}`, ids and repo-relative paths only, never key text). Keys reach only the scorer. A bad file exits 2 naming it; a missing input or key file is a `skipped: missing` row and the run continues. Each item that ran appends one history line with `source=regset`, `set_id`, `key_basis` (`official` for human keys, `generated: ...` for model-made keys, which `run-stats board` labels `key (generated)`), git and prompt (default history `plans/run-history.jsonl`). `regression` counts a pass drop only for items that ran in both summaries, so a skipped item is no regression. Without `--set` the run is the old `discover()` over `--inputs/--keys`.
- Solve gate (TASK-078, REQ-0024): `ingest --exam-out --min-verification verified|any` (default engine.json `min_verification`, `verified`; api default `any`) leaves questions below the level out of the exam text (`rejected` always; only when the doc carries `verification`; a missing key then = unverified). Left-out items go to the sidecar `skipped` [{printed, status, reasons}] (key only when non-empty) and stderr `WARN: skipped_unverified`; `solve` copies them to result.json `skipped_unverified` + `summary.skipped_unverified` and a report line; they never affect pass/fail/exit code.
- Provenance sidecar (TASK-048): `exam.py ingest --exam-out E.md` also writes `E.md.assembly.json` (`{schema: "assembly/1", exam, questions: [{id, printed, source_pages, assembly_status complete|uncertain, validation_status passed|failed, reasons}]}`, one row per exam question; `source_pages` is `[]` on the text path (no per-question page); not written for an exam-format Markdown source); `api.assembly(doc, cfg)` shares its selection with `to_exam_text` (failed <=> `[Incomplete:` marker). `ingest-inspect` gets an `## Assembly` table; `solve`/`plan-import` copy the sidecar next to the exam to `input/assembly.json`. Dev prompts only: refine.md rule 12 (no running headers/footers; voids cached refine pages) and a `missing_text:` decline bullet in dev system.md (en, vi); release v1.0.0 untouched. TASK-065 stage 1: the row gets `structure` (list of `range_cut_by_section`, `instruction_override`, `range_overrun`; key only when non-empty; flags never decline). `api._share_context` keeps a range inside its section and keeps a question's own context in its text; `parser.parse_exam` reads options of a labelled question only after `### Question text`.
- `exam.py ingest-refine` (TASK-047): a cut last question is re-read whole by one window call over its pages (rule 11 of `prompts/dev/ingest/refine.md`, dev channel only, no release copy); flags `--no-window` (pre-47 bridge only), `--no-recover` (no pages outside `--pages`), `--cache DIR` (page reply cache, key = model + prompt + image hashes; `--real` only, mock runs never touch disk); `--dry-run` prints `pages P, windows planned W (native), calls <= ..., est cost`. `<out>.trace.json` rows: `{ok, cls, cost_usd, text, reason, page, pages, png_sha256, cached}` (separate from the solve plan-run calls/). `--mock FILE`: a JSON list is replayed in order, a JSON object maps the page label (`"8"`, window `"7-8"`) to a reply. Optional output fields: question `window`, refined `windows`, `recovered_pages`; absent when no question is cut.
- OCR route quality (TASK-051): scanned PDF pages are read by tesseract (`vie+eng` wanted; `tesseract --list-langs` must list `vie`). Text is rebuilt from char boxes (`OCR_GAP = 0.15`), running headers/footers are removed OCR-tolerantly, and a question touching an OCR page gets `ocr_doubt` = sorted kinds `glued` | `chars` | `furniture` | `lang_missing` | `low_conf` | `token` (hard marker: `[Incomplete: missing_text ocr_doubt <kind>]`, sidecar `uncertain`, engine declines it; no AI fallback). `lang_missing`: `vie.traineddata` absent -> every OCR question marked, warning `ocr_language_missing` at level `error`; put `vie.traineddata` in `/usr/share/tesseract-ocr/<ver>/tessdata/` or `$TESSDATA_PREFIX` (or config `tessdata`), the engine never fetches it; the run still completes. TASK-071 misread signals: `low_conf` = a word the tesseract CLI TSV (`--psm 3`, same pixels, +~1 s/page, config `ocr_conf` `auto`|`off`, info warning `ocr_conf_unavailable` when the binary/run fails) scores below `OCR_LOW_CONF` (60; per-language override: top-level `ocr_low_conf` `{code: n}` in `config/lang.json`); `token` = glyph shape (`h0n`, `$o`; `$6`/`S6` only at low confidence). Soft flag `option_parity` (assembly `structure`, solved, board parse flag): one option starts with another glyph class than the rest, or an odd option count. Text is never corrected; refined route unchanged. Measurement helpers: `tests/unit/ocr_gap_sweep.py` (gap), `tests/unit/ocr_before_after.py [out.tsv]` (before/after real-error, unmarked-wrong, glued, false alarm; vie+eng, synthetic), `ocr_before_after.py --calibrate sweep.tsv arms.tsv` (71.5 floor/margin sweep, families A-D x 30).
- Exam-kind data (TASK-062): `config/lang.json` (`{"extra": {code: {slot: [words]}}}`, words not regex; vi+en stay code literals, data only adds; slots question/group/range/intro/part/page/true/false/paragraph/figure/needs_text/scripts) read by `utils/langtable.py` for segment, refine, pdf page furniture + garble scripts, verdicts, refcheck. `config/subjects.json` optional `answer_shapes` (`tf4`, `number`) and `label`; `config/genexam_profiles.json` holds the gen-exams profiles (subject, prompt, qa_prompt, topics, check reply|mc4|mc, blind, exam_type, level, lang, instructions, grading_line); a bad profile is GenError `bad_profile`. Golden: `tests/unit/test_generality_golden.py`.
