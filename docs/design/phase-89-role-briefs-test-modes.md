# Phase 89 - role briefs use the fast test modes (REQ-0097)

## Goal
Roles stop running the 6-minute plain unittest suite; they use the modes from phase 88.

## Design
- 89.1 In `.claude/agents/{coder,designer,tester,verifier}.md` replace the `- Tests: python3 -I -m unittest discover -s tests/unit` line (inside the generated `agent-setup:project` block) by: iterate `--affected`, finish `--fast`, `--full` is started by the main session once per task (docs/guide/testing.md).
- 89.2 tester.md step 'Run python3 -I -m unittest discover ...' becomes `--fast`, known failures print as known, a NEW line is a defect; do not run the plain suite or --full; cite main's result file if present.
- 89.3 docs/guide/workflow-roles.md section 11: the briefs now name the modes; regeneration caveat.
- Constraint: roles cannot create a git worktree (guard), so --full stays with main. The block is regenerated by an `agent_setup init` from an external profile: re-apply the wording there.

## Plan modes
No impact on single-source or pipeline plans (documentation of how roles test).

## Failure modes
A later `agent_setup init` overwrites the block -> the plain command returns; mitigated by the section 11 note and AC4 grep check.

## Unit tests
None (wording). Check: grep -c 'unittest discover' in the four briefs = 0 outside the tester's fallback text.
