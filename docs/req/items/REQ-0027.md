## Requirement
WHEN the engine is changed, the harness SHALL be able to generate new Vietnamese-style exams per subject (English, math, physics, informatics, literature) with a separate answer key, run the unchanged engine on them, score them key-only, and record each failure as a lesson, so the engine improves from real solve attempts and not only from code review.
Eval keys never reach the solver; generated exams stay out of few-shot files; every real run needs the user's go.

## Acceptance
- [ ] AC1: a generator command writes N exams per subject in `examples/FORMAT.md` form into `evals/inputs`, with keys only in `evals/keys`, a `generated: true` marker and the seed/prompt version; $0 `--mock` and `--dry-run` modes.
- [ ] AC2: a generated exam passes the format checker and a key-leak check (no key text in the input).
- [ ] AC3: `benchmark` runs the generated set and reports pass/fail per item and per subject, separate from the hand-made set.
- [ ] AC4: each FAIL or UNCERTAIN item is written to a lessons file (item, cause class: engine bug / bad key / bad exam / solver variance, evidence), and the loop lists open lessons.
- [ ] AC5: one real round (budget cap, user go) shows at least one lesson turned into an engine fix, with before/after benchmark numbers.

## Open questions
- [ ] Q1: generator model: same Claude as the solver (risk: shared blind spots, wrong keys) or a different route? Recommend: Claude with a code oracle for math/physics/informatics keys; English/literature keys marked "reviewed: no" until you spot-check.
- [ ] Q2: round budget? Recommend: 10 exams x 5 subjects, about $3 per round, with your go each time.
