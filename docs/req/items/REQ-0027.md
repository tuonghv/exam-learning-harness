## Requirement
WHEN the engine is changed, the harness SHALL be able to generate new Vietnamese-style exams per subject (English, math, physics, informatics, literature) with a separate answer key, run the unchanged engine on them, score them key-only, and record each failure as a lesson, so the engine improves from real solve attempts and not only from code review.
Eval keys never reach the solver; generated exams stay out of few-shot files; every real run needs the user's go.

## Acceptance
- [x] AC0: concept round first: 1 subject (math), 3 generated exams, one real round under $1, a short findings note; the next round grows only from what it shows.
- [x] AC1: a generator command writes N exams per subject in `examples/FORMAT.md` form into `evals/inputs`, with keys only in `evals/keys`, a `generated: true` marker and the seed/prompt version; $0 `--mock` and `--dry-run` modes.
- [x] AC2: a generated exam passes the format checker and a key-leak check (no key text in the input).
- [x] AC3: `benchmark` runs the generated set and reports pass/fail per item and per subject, separate from the hand-made set.
- [x] AC4: each FAIL or UNCERTAIN item is written to a lessons file (item, cause class: engine bug / bad key / bad exam / solver variance, evidence), and the loop lists open lessons.
- [ ] AC5: one real round (budget cap, user go) shows at least one lesson turned into an engine fix, with before/after benchmark numbers.
- [ ] AC6: each generated solution gets its own QA before it enters the set: step-by-step review by an independent call plus the code check; a wrong step or key marks the exam `qa: fail` (kept for analysis, not benchmarked) and is counted per round, so wrong solutions are known and the generator prompt improves from them (RAW-00090).
