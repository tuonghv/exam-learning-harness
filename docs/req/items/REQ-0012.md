## Requirement
WHEN the engine is restructured, the harness SHALL provide one Python package `exam_engine` (modules grouped by responsibility: `cli`, `engine`, `adapters/claude`, `pipeline/{parser,router,solver,verifier,reporter}`, `core`, `utils`) with prompts, schemas, config, tests and runtime artifacts in separate top-level folders, using `tmp/engine-architecture.md` as the reference and a design adapted to this repo's constraints (stdlib only, Python 3.8, `python3 -I`, tester -> verifier workflow, approved `examples/FORMAT.md`). Behaviour, tests and entry points keep working; every Claude call goes through one adapter; adding a subject needs a prompt file and a config entry, not new engine code.

## Acceptance
- [ ] AC1: `docs/design/phase-6-engine-structure.md` maps every existing file (tools/examples/*.py, prompts, tests, schemas) to its new place, records what differs from `tmp/engine-architecture.md` and why, and has no open question
- [ ] AC2: one CLI entry point with subcommands solve, parse, verify, report; the old `tools/examples/*.py` commands still work (thin shims) and print the same results
- [ ] AC3: every `claude -p` call goes through `adapters/claude.py`; a test greps the package and finds no other subprocess use of `claude`
- [ ] AC4: prompts live in top-level `prompts/` (never under `docs/prompts/`), schemas in `schemas/*.json`, config in `config/*.json`; code reads them by path from one settings module, nothing hardcoded
- [ ] AC5: a new subject is added by a `prompts/subjects/<s>.md` file and a `config/subjects.json` entry only (proved by a test that adds a temporary subject)
- [ ] AC6: all 108+ existing tests pass unchanged in meaning after each move (regression net), plus tests for the new CLI and settings; `README.md` documents the structure and usage
