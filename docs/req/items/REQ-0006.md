## Requirement
<!-- Clear, testable statement in one language (English preferred). EARS: "WHEN <trigger>, the <system> SHALL <response>." -->
WHEN a session starts, resumes or compacts, the harness SHALL inject only a bounded summary (SessionStart <= 2 KB, ledger compact context <= 1 KB, per-prompt/per-tool hook output one line) so that auto-compaction is triggered by real work, not by hook output or fixed per-turn overhead; the root cause SHALL be recorded with byte measurements from the session transcript.

## Acceptance
<!-- Each item objectively verifiable. VERIFIED requires every box ticked. -->
- [ ] AC1: Root-cause table in Design with transcript measurements: 8 auto-compactions on 2026-10-29 (preTokens 478,799 / 710,695 / then ~67k each), `session-start.sh` output 1,671,706 bytes per run while sample state was live, per-turn attachments (skill_listing ~28 KB, instructions ~10 KB, hook outputs).
- [ ] AC2: `.claude/hooks/session-start.sh` output is capped at 2,000 bytes on any state (test: a fixture state with 200 tasks prints <= 2,000 bytes and ends with a truncation note).
- [ ] AC3: `.claude/req/hook_context.py` compact output is <= 1,000 bytes: focus REQ id, title, AC done/total and next step, no full AC text.
- [ ] AC4: UserPromptSubmit and PreToolUse hook outputs are one line each (or empty) on a normal turn.
- [ ] AC5: The `autoCompactWindow` decision (Q1) is recorded and applied only as answered; global `~/.claude/settings.json` changes only with the user's confirmation.
- [ ] AC6: Post-fix measurement: SessionStart output bytes and the number of compactions over a comparable session are recorded in Evidence, showing the reduction.
