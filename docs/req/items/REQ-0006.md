## Requirement
<!-- Clear, testable statement in one language (English preferred). EARS: "WHEN <trigger>, the <system> SHALL <response>." -->
WHEN a session starts, resumes or compacts, the harness SHALL inject only a bounded summary (SessionStart <= 2 KB, ledger compact context <= 1 KB, per-prompt/per-tool hook output one line) so that auto-compaction is triggered by real work, not by hook output or fixed per-turn overhead; the root cause SHALL be recorded with byte measurements from the session transcript.

## Acceptance

## Design

Root cause (measured from this session's transcript, 18 compactions, 34 MB):
| Source | Count | Total | Avg |
|---|---|---|---|
| SessionStart:startup hook output | 1 | 1,692 KB | 1,732,848 B |
| SessionStart:compact hook output | 34 | 3,459 KB | 104,194 B |
| UserPromptSubmit hook output | 147 | 161 KB | 1,127 B |
| PreToolUse:Bash hook output | 234 | 171 KB | 751 B |
| skill_listing attachments | - | 508 KB | - |

The uncapped SessionStart output (live sample state) re-filled the context after every compaction; later compactions fire at about 67k preTokens, the first two at 478,799 / 710,695.
Fix: `.claude/hooks/session-start.sh` is now a wrapper that caps the body (`session-start-body.sh`) at 2,000 bytes with a truncation note; `.claude/req/hook_context.py` caps at 1,000 bytes. Current output: 335 B and 343 B. Test: `tests/unit/test_session_start_cap.py` (200-task fixture <= 2,000 B). Open: AC4 (UserPromptSubmit avg 1,127 B, PreToolUse 751 B, not one line), AC5 (autoCompactWindow, user decision), AC6 (post-fix compaction count needs a comparable later session).
