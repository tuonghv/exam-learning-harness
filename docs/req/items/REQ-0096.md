## Requirement
WHEN a developer or role runs the unit tests, the system SHALL offer a fast path so a normal change is checked in well under a minute instead of the ~6 minute full suite: (a) tests are measured and the slow ones tagged in one registry; (b) `tools/run_tests.py --fast` skips the tagged slow tests; (c) `--affected` runs only the tests that cover the changed source files (git diff based, with a conservative map and a safe fallback to fast+related); (d) the full suite stays the gate before VERIFIED/DONE and is run once in the background with a persisted result, never run twice per task; (e) role briefs and the workflow docs say which mode to use when (user, RAW-00271: the full suite is slow, blocks development, grow productivity).

## Acceptance
- [x] AC1: a measured timing report (per test and per file, total) is produced by a script, committed as a small summary (no data from exams), and shows where the ~370 s goes.
- [x] AC2: slow tests (threshold in the registry, e.g. > 2 s) are tagged in `config/test_tiers.json` (single source) and `--fast` skips them; fast total reported.
- [x] AC3: `--affected` maps changed files to test files (naming + import scan), prints the chosen tests and why, falls back to --fast when a changed file has no mapping.
- [x] AC4: the gate mode `--full` equals today's `python3 -m unittest discover -s tests/unit`; its result is written to a file with the rc and the Ran/FAILED lines (the pattern we used by hand), and a second `--full` on an unchanged tree is not needed (hash of tracked source+tests -> reuse the last result; stale if anything changed).
- [x] AC5: a check proves no test is lost: fast + slow = all tests (counts equal to discover), and a test that is added without a tier still runs in --fast (default fast).
- [x] AC6: docs/guide + coder/tester role briefs updated: development loop = --affected, before commit = --fast, gate = --full once in the background.
- [x] AC7: the 4 known pre-existing failures are listed as known (config), reported as such, not as new failures.

- [x] AC8: measured (RAW-00271 follow-up): 6 tests = ~300 s of 369 s (test_window_golden 156 s in one test, test_ocr_respace 77 s, test_completeness_measure_pdf 77 s); those 3 files are the slow tier. The gate `--full` runs in a throwaway git worktree of the committed tree (as already done in /home/tuonghv/Documents/git/online-system/_code-security-scanner; user RAW-00273, read-only reference) in the background, so development continues in the main tree; the result is persisted with the tree hash, rc and Ran/FAILED lines, and the worktree is removed afterwards.
