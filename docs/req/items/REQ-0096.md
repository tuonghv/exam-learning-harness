## Requirement
WHEN a developer or role runs the unit tests, the system SHALL offer a fast path so a normal change is checked in well under a minute instead of the ~6 minute full suite: (a) tests are measured and the slow ones tagged in one registry; (b) `tools/run_tests.py --fast` skips the tagged slow tests; (c) `--affected` runs only the tests that cover the changed source files (git diff based, with a conservative map and a safe fallback to fast+related); (d) the full suite stays the gate before VERIFIED/DONE and is run once in the background with a persisted result, never run twice per task; (e) role briefs and the workflow docs say which mode to use when (user, RAW-00271: the full suite is slow, blocks development, grow productivity).

## Acceptance
- [ ] AC1: a measured timing report (per test and per file, total) is produced by a script, committed as a small summary (no data from exams), and shows where the ~370 s goes.
- [ ] AC2: slow tests (threshold in the registry, e.g. > 2 s) are tagged in `config/test_tiers.json` (single source) and `--fast` skips them; fast total reported.
- [ ] AC3: `--affected` maps changed files to test files (naming + import scan), prints the chosen tests and why, falls back to --fast when a changed file has no mapping.
- [ ] AC4: the gate mode `--full` equals today's `python3 -m unittest discover -s tests/unit`; its result is written to a file with the rc and the Ran/FAILED lines (the pattern we used by hand), and a second `--full` on an unchanged tree is not needed (hash of tracked source+tests -> reuse the last result; stale if anything changed).
- [ ] AC5: a check proves no test is lost: fast + slow = all tests (counts equal to discover), and a test that is added without a tier still runs in --fast (default fast).
- [ ] AC6: docs/guide + coder/tester role briefs updated: development loop = --affected, before commit = --fast, gate = --full once in the background.
- [ ] AC7: the 4 known pre-existing failures are listed as known (config), reported as such, not as new failures.

## Open questions
- [ ] Q1: Where does the time go and is it safe to skip? -> answer by AC1 first (measurement), no guess.
- [ ] Q2: Gate rule: --full required once per task before VERIFIED only, or also before every commit? -> recommend (best): once per task before VERIFIED (cached by tree hash), --fast before every commit.
