## Requirement
<!-- Clear, testable statement in one language (English preferred). EARS: "WHEN <trigger>, the <system> SHALL <response>." -->
WHEN the user asks how the engine improved, the system SHALL print one scoreboard per exam kind and run: coverage (answered/declined/malformed), quality (key accuracy where a key exists, otherwise QA/proxy agreement and false-alarm rate), cost, and the change since the previous or a named baseline run; IF coverage rises while quality falls beyond the noise rule (phase 56), THEN it SHALL flag the change as a quality regression.


## Acceptance
<!-- Each item objectively verifiable. VERIFIED requires every box ticked. -->
- [x] AC1: `run-stats board` (or extension of compare/trend) prints coverage and quality side by side with delta and verdict (better / same / regression), using only saved runs and history; no AI call
- [x] AC2: coverage-up/quality-down case is flagged, with a unit test using synthetic runs
- [x] AC3: (split to REQ-0072) a fixed small keyed regression set (trial exam with key, synthetic keyed exams of other kinds) is re-scored after each engine change and appended to the history so quality is measured on real keyed data, not only on DGNL which has no key
