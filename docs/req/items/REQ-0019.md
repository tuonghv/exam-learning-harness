## Requirement
WHEN a PNG, JPG, JPEG or WEBP file is ingested, the image adapter SHALL validate it (magic bytes, readable, size), keep the original unchanged, and emit a canonical document whose page is an image asset reference with source metadata and dimensions, without mandatory OCR; and the solve step SHALL pass the image to `claude -p` through its supported image input so Claude reads questions, formulas, diagrams and options directly. OCR runs only when needed for indexing or validation; resizing or splitting happens only for oversized images and keeps readability, with every piece referenced and nothing silently dropped.

## Acceptance
- [ ] AC1: PNG, JPG, JPEG and WEBP files ingest to a valid canonical document (image asset ref, sha256, size, format, original path); the original file bytes are unchanged
- [ ] AC2: an unreadable, truncated, unsupported-extension or extension-mismatched file and a missing asset give structured errors; visual content is never silently discarded
- [ ] AC3: the image reaches `claude -p` through a documented mechanism that keeps the existing isolation (empty cwd, tools off); a mock test shows the image block in the request and no key text; an unsupported path is reported, not skipped
- [ ] AC4: an image above the size limit is resized or split into referenced pieces recorded in the document; smaller images are untouched
- [ ] AC5: OCR (tesseract vie+eng) is optional and off by default; when run, its text is stored as extracted content, never replacing the image
- [ ] AC6: tests with synthetic images ($0, no real call) cover the cases above; a real image call is made only with the user's go

## Open questions
- [x] Q1: How is the image given to claude -p? `claude --help` shows `--input-format stream-json` only. Recommended: send base64 image blocks over stdin with stream-json, keeping tools off and the empty cwd (no file path access, no repo read). Alternative: allow the Read tool on a temp dir copy (wider access, needs your approval under the blocking rule). Why: base64 keeps the isolation rule intact. -> accepted as recommended: base64 image blocks over stdin (stream-json), tools off, empty cwd (user, RAW-00052, 2026-10-29)
- [x] Q2: Image decoding and resizing: Pillow is not installed. Recommended: stdlib only for header checks (PNG/JPEG/WEBP dimensions, size) and no resize unless Pillow or pymupdf is present (lazy import, `missing_dependency` error otherwise); size limit defaults to 5 MB per image. Why: same rule as PDF/DOCX. -> accepted as recommended: stdlib header checks, 5 MB limit, resize only via lazy pillow/pymupdf (user, RAW-00052, 2026-10-29)
