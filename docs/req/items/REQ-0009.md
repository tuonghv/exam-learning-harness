## Requirement
WHEN the maintainer runs the benchmark, the engine (EPIC-003: Python code plus Claude AI through `claude -p`, RAW-00032) SHALL solve every example of the set with real `claude -p` calls, check each answer against the key after the decision (deterministic SCORE), and report the actual per-item and per-subject PASS/FAIL/UNCERTAIN counts as measured. IF a prompt or engine rule is changed to raise the score, THEN the change SHALL cite the measured failing item and be re-measured on the same items; no change is justified by an assumed answer. Per-subject results SHALL be compared with the previous run so a regression is visible.

## Acceptance
- [x] AC1: a benchmark command runs the engine over `examples/` and `evals/inputs/` (few-shot items are used only as a smoke set, never as accuracy proof) and writes `work/exam-runs/<date>/summary.json` plus a readable report with real counts per subject and per item (actual solver answer, key answer, verdict, retries used)
- [x] AC0: the work is split by strength: `claude -p` reads the question and reasons the answer; Python code does everything checkable (schema, completeness, recompute of `expr`, option and quote checks, retries, scoring, report). My own hand-solved answers are never evidence; only the engine's recorded run is
- [ ] AC0b: the Python script itself builds each call: `tools/examples/prompts/solve.md` + the exam file text, sent to `claude -p` (prompt on stdin, `--output-format json`), and reads the answer JSON back from the reply (RAW-00033); no manual copy-paste of prompts or answers
- [x] AC2: the report states for each item whether the check was a code oracle, a key match, or a Claude review only; a Claude-only agreement is never counted as verified
- [x] AC3: a failed item shows the solver answer, the key, and the first failing check, so the cause is read from evidence, not assumed
- [x] AC4: every prompt/engine change after a run records the item it fixes in `docs/report/` (item id, before, after) and a rerun shows the result; a run whose score fell is flagged as a regression
- [x] AC5: cost gate: a real run needs the user's go; the command prints the number of `claude -p` calls and a cap before starting, and `--dry-run` and `--mock` cost $0
- [x] AC6: the benchmark runs with the eval keys read only by the scorer; a grep of every solver prompt of the run for key text is empty
