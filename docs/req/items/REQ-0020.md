## Requirement
WHEN a canonical document exists (any format), the system SHALL provide `scripts/exam.py ingest-inspect <doc.json|file> [--out report.md]` that writes a readable per-page report (status, text per block with kind and origin, warnings, asset list with bbox, OCR vs native per page), detects parts of one file (exam pages versus an embedded answer or solution guide, by headings such as 'Hướng dẫn giải' / 'Đáp án' / 'Lời giải'), flags suspicious extraction (broken math, split formulas, one-symbol lines, stray characters, non-consecutive numbering) with page and block references, and offers `--pages 1-4` so only the exam part is converted for solving. It SHALL use local code only (no Claude call, no cost) and never alter the document.

## Acceptance
- [ ] AC1: `ingest-inspect` on work/ingest-trial/doc.json reproduces the page-by-page report (current out.md content plus a summary header: pages, status per page, counts of warnings, assets, questions found)
- [ ] AC2: it detects that pages 5-12 of the trial PDF are a solution guide and prints a clear 'answer key present: pages 5-12' notice; with `--pages 1-4` `ingest` and `to_exam_text` use only those pages, and a solve of an input containing detected key pages without `--pages` is refused with a message (key-leak guard)
- [ ] AC3: it lists suspicious spots (formula lines split into single symbols, option lines without text, numbering gaps) with page and block id so a human can check against the PDF
- [ ] AC4: it is read-only (document and source untouched), needs no network, no Claude call; tests with synthetic PDFs cover guide detection, page ranges, suspicious-line detection and the refusal
- [ ] AC5: the report states that extraction heuristics are not proof of correctness

## Open questions
- [x] Q1: Output format: Recommended: keep JSON (canonical doc) as the machine contract and Markdown as the human report; Claude reads the JSON blocks as text plus page images. Why: JSON is lossless for code and validation, Markdown is easy for you to compare with the PDF; no extra tool or dependency needed. Cost: $0 (local code; PyMuPDF is AGPL-3.0, free for this internal use, but redistributing the harness would need a commercial licence or AGPL compliance). -> accepted as recommended: JSON canonical + Markdown report (user, RAW-00061, 2026-10-29)
- [x] Q2: Should the page range and key-guard be mandatory for any PDF where a guide is detected?
