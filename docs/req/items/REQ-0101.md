## Requirement
`plans/<exam>/main` and `reports/<exam>/main` SHALL hold the latest PUBLISHED runs of an exam; development and test runs (versions v3, fix_abc, ...) go to other lines and SHALL NOT touch main; a run in main happens only when the user asks, as a new run id (user, RAW-00284: "main also the latest public your report ... test in dgnl2026/v3 ... prevent to impact to main ... later when I ask you run then should run in main with new run id").

## Acceptance
- [ ] AC1: any command that writes into a line named `main` (solve, report, report-pack, import) refuses unless `--publish` is given, and says: use `--line <name>` for tests, or `--publish` when the user asked; dev lines are unaffected. Reading/listing never needs it.
- [ ] AC2: `exam publish EXAM --from LINE [--view ...]` (or `report-pack --publish --from-line LINE`) builds a NEW report run in `reports/<exam>/main/` from the latest plan runs of LINE at $0 (the plan runs stay where they were solved; the report's run.json links them), keeping all earlier main runs; a real re-solve in main is `solve --line main --publish` (cheap when the solve cache hits).
- [ ] AC3: the agent rules: tests/experiments always pass `--line <dev>`; a main run only on the user's request; written in docs/guide (workflow-roles section) and in the toolkit reference; the unit tests and the mock/dry-run default path keep working (tests use tmp roots).
- [ ] AC4: `run-list` marks main runs as `published` and dev lines as `dev`; INDEX.md of the exam lists main first.
- [ ] AC5: announced to the user (old behaviour: default line main with no guard -> new: guard + publish).

## Open questions
- [ ] Q1: Should the guard refuse a write to main without `--publish` (best), or only warn? -> recommend (best): refuse; the default line stays `main` for reading (run-list, last_solved), but writes need --publish, so a test can never silently change the published line.
- [ ] Q2: Publishing = a report run built from a dev line's plan runs (best, $0, e.g. publish v3 after you accept it) and a real re-solve in main only when you ask; is that what you mean by "run in main with new run id"? -> recommend (best): yes, both, with the solve cache making an unchanged re-solve cost $0.
