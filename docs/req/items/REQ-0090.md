## Requirement
Follow-ups from TASK-083 (REQ-0089), all low severity: the "already solved" message SHALL report the original paid run (not a newer cached run); `engine.build_result` SHALL tolerate a runner without `cache`; a cached `cost_usd` SHALL be range-checked (finite, >= 0) else treated as a miss; refine and boundary reply caches SHALL not key on unpinned aliases; the metrics `cache: hits=` line SHALL have a direct test.

## Acceptance
- [ ] AC1: after a paid run and a cached `--yes` re-run, the "already solved" line shows the paid run's cost and calls.
- [ ] AC2: `build_result` with a runner lacking `cache` does not raise.
- [ ] AC3: a cache entry with negative, NaN or non-number `cost_usd` is a miss (unit test).
- [ ] AC4: refine/boundary cache keys use a pinned model ID, or the run refuses the alias.
- [ ] AC5: a unit test asserts the `cache: hits=N saved=$X` metrics line.
