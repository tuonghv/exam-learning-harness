## Requirement
WHEN a language or subject variant of a prompt is added, a validator script SHALL prove it exposes the same interface (same placeholders, same required sections, same output JSON schema) as the base prompt, so one engine runs every variant.

## Acceptance
- [x] AC1: layout `prompts/<channel>/lang/<code>/<rel>` (variants) over default root files, plus `prompts/contract.json` (language-neutral markers and the output-example schema per prompt)
- [x] AC2: `scripts/exam.py check-prompts` fails (exit 1) on a missing marker, a different output-JSON key structure or a stray/ill-named variant file; exit 0 when all variants match
- [x] AC3: the engine picks the variant by subject language (config/subjects.json) with fallback to the base; output JSON always validates against the same SOLVE_OUT schema
- [x] AC4: test: a deliberately broken variant (placeholder dropped) makes check-prompts exit 1; mock runs of vi and en variants give schema-valid results

## Open questions
- [x] Q1: Variant axis: language (vi/en) first, subject overlay second (current `subjects/*.md`). Recommended: yes, because language changes wording but subject only adds rules. Accept? -> accepted as recommended (user, 2026-10-29, RAW-00046)
- [x] Q2: Instructions language for Vietnamese subjects: English instructions plus an `answer_language` rule vs fully Vietnamese prompts. Recommended: English instructions + answer_language, because placeholders stay identical and it costs fewer tokens; add a vi variant only if the benchmark shows a gain. -> accepted as recommended (user, 2026-10-29, RAW-00046)
