## Requirement
WHEN the maintainer runs `exam_run.py <exam.md>`, the engine (Python + `claude -p`, RAW-00025/32/33/35) SHALL build the call from `tools/examples/prompts/solve.md` plus the exam text, send it to `claude -p` (prompt on stdin, `--output-format json`), extract the answer JSON, validate it against the schema, run the code checks (completeness, option and quote checks, recompute of `expr`), run QA, decide PASS/FAIL/UNCERTAIN with a configurable retry limit, and score against a key only after the decision. Design: `docs/design/phase-2-exam-pipeline.md` sections 2.1-2.4 (modules exam_llm, exam_schema, exam_run, exam_checks, exam_qa; the parser is `exam_parse.py` from REQ-0002).

## Acceptance
- [x] AC1: `exam_llm.run_claude()` sends prompt on stdin with no shell, a timeout and a call cap; `extract_json` accepts strict JSON, one fence or outer braces, and rejects malformed output (tests with mocked output)
- [x] AC2: schema validation rejects a missing question, a wrong type and a model-set `verified`; an id that is not in the exam is ignored and never scored; a rejected reply is retried up to the configured limit, then the item is UNCERTAIN
- [x] AC3: code checks run without Claude: multiple choice A-D, ordering form, quote present in the Passage, `expr` recomputed with a safe arithmetic evaluator; PASS needs a code check, Claude agreement alone ends UNCERTAIN
- [x] AC4: the eval key is never in any prompt (solver, QA, retry); a test greps every recorded prompt for key text and finds none; SCORE reads the key only after DECISION and a key mismatch never triggers a retry
- [x] AC5: `--mock <responses.json>` and `--dry-run` cost $0; a real call needs `--real` and prints the call count and cap first
- [x] AC6: focused unit tests from the design (correct, incorrect, missing question, malformed JSON, QA fail/uncertain, retry exhaustion, score, schema) pass with mocked LLM output only: `python3 -I -m unittest discover -s tools/examples/tests`
