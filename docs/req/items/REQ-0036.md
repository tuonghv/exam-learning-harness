## Design
Gap analysis: (1) router.language (src/exam_engine/pipeline/router.py:40) = exam header `Language:` else subject policy else "vi"; config/subjects.json hardcodes vi for math/physics/literature/informatics/vietnamese/science and en for english, so a new subject or an English-language Math exam is wrongly vi; solver.md:45 already supports `auto`. (2) The real DGNL English run (work/dgnl-real/run-English/result.json) is explained in Vietnamese because its exam file carries `Language: vi` (line 8): the header silently beats the subject policy; examples/FORMAT.md:28 documents it as optional. (3) No CLI override: user cannot ask for translation per run. (4) reporter.py labels are English-only, so a Vietnamese learn view mixes languages (violates consistency). (5) result.exam.language may be "auto", the reporter then needs the real language. Revised by RAW-00125: the real English run in vi is already the wanted default, so gap (2) becomes only a documentation point and the config change is just english `en` -> `vi`. Smallest fix: add `--lang` to the run/solve entry that sets exam fields Language (highest precedence, pass-through, no solver change); add LABELS {vi,en} + a tiny detector (Vietnamese diacritics in explanations -> vi) in reporter.py used only by the learn view. Needs phase-29 learn view first (TASK-029). Out of scope: translating existing results, re-solving.
