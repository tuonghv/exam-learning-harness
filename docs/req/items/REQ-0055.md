## Requirement
WHEN a solve run finishes for an exam subject (math, DGNL sections, English, ...), the system SHALL produce at a standard path a review pack with one small file per question (printed number, source page, extraction status, the engine's answer, a short solution, confidence/doubt, flags) plus a per-subject index, and SHALL read a simple feedback file the user fills (agree / disagree / unsure, correct answer, defect kind: extraction, solution, flawed question, comment) to compute agreement, list the engine's defects and feed improvements; after every engine change the standard path is re-run on the small slices of each subject and the user is asked to review. Source: user RAW-00156.

- [ ] AC2: feedback format inside the same subject file, per question one line `Your review: verdict agree|disagree|unsure | correct A-D | kind extraction|solution|flawed|other | note`; `exam.py review-apply` reads those lines from `review/<exam-id>/<subject>.md` (no separate feedback file), reports agreement per subject with Wilson, the disagreement list by printed number and kind, writes `improvements.md` (what the human found: grouped by kind, with the question numbers) and never changes solver inputs or eval keys (human verdicts live outside solver inputs; stored as a human key file under evals/keys only when the user says so)
