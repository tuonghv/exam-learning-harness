## Requirement
WHEN the engine writes a plan, it SHALL put each plan run under `plans/<exam>/runs/<plan-run-id>/`; WHEN it builds reports, it SHALL put each report run under `reports/<exam>/run-<report-run-id>/`, so one exam holds many plan runs and, for each plan run, many report runs (rebuilt at $0), and every report run records which plan run it came from (user, RAW-00267; example paths plans/dgnl2026f/runs/20261103-175009 and reports/dgnl2026f/run-20261025-214704).

## Acceptance
- [ ] AC1: new solves write `plans/<exam>/runs/<plan-run-id>/` (plan.json, config, input, calls, results); the exam-level `plans/<exam>/cache/` stays at exam level.
- [ ] AC2: `exam report` / `report-pack` write `reports/<exam>/run-<report-run-id>/`; its manifest (INDEX.md + a small run.json) names the plan run, the view and the engine/registry version.
- [ ] AC3: two report runs of the same plan run coexist; a rerun never overwrites an older report run unless the same id is given.
- [ ] AC4: all readers (last_solved, run-stats, review-pack, plan-import, scorer, report_kinds, check_report_pack, solve cache) accept old layouts (plans/<exam>/<run>/..., reports/<exam>/<run>/<report-id>) and the new one; no old folder is moved.
- [ ] AC5: run ids follow one format (see Q3) and are registered in the report-kinds guide; INDEX.md lists each report run with its plan run.
- [ ] AC6: unit tests for new and legacy layouts, last_solved on both, two report runs per plan run; QA recount of a rebuilt pack.

## Open questions
- [ ] Q1: What does `run-<report-run-id>` hold? (a) one report run = one folder with its own timestamp id that points to a plan run, so many report runs can point to the same plan run; (b) the report folder is named after the plan run (`run-<plan-run-id>/<report-id>/`). -> recommend (a, best): matches your example (different timestamps for plan and report) and lets one plan produce many reports.
- [ ] Q2: Existing folders (plans/dgnl2026f/out-Math, reports/dhqg2024/...): move them into the new layout, or leave them and read both? -> recommend (best): leave them, new runs use the new layout, INDEX marks old ones legacy (nothing lost, nothing to re-verify).
- [ ] Q3: Run id format: `YYYYMMDD-HHMMSS` as in your examples (UTC), replacing the current `20261107T035802Z`? -> recommend (best): your format in UTC; old ids stay readable.
